# داشبورد کانال‌های تبلیغاتی

داشبورد داخلی برای جمع‌آوری و مدیریت یوزرنیم کانال‌های تلگرامی، جهت استفاده در **Telegram Ads**.

تیم شما کانال‌ها را داخل گروه‌های موضوعی ثبت می‌کند، سیستم تکراری‌ها را می‌گیرد،
کانال‌های ضعیف با نمرهٔ منفی ته لیست می‌روند، و در پایان یک لیست تمیز برای آپلود در پنل تبلیغات دارید.

## امکانات

**گروه‌بندی**
- ساخت گروه با عنوان، توضیحات، رنگ برچسب و **متن تبلیغ اختصاصی**
- بایگانی کردن گروه‌های تمام‌شده بدون حذف داده

**ثبت یوزرنیم**
- افزودن تکی یا **چسباندن لیست انبوه** (هر خط یک کانال)
- پذیرش فرمت‌های `@name`، `t.me/name`، `https://t.me/name`، `telegram.me/name` و `name`
- **بررسی تکراری در همان گروه** — رد می‌شود و نشان می‌دهد چه کسی و کِی ثبتش کرده
- **هشدار تکراری بین گروه‌ها** — اگر کانال در گروه دیگری باشد، اطلاع می‌دهد و اجازهٔ ثبت آگاهانه می‌گیرد
- گزارش خط‌به‌خط از موارد اضافه‌شده، تکراری و نامعتبر

**نمرهٔ منفی**
- هر کاربر می‌تواند به هر یوزرنیم یک نمرهٔ منفی بدهد (و پس بگیرد)
- یوزرنیم‌های دارای نمرهٔ منفی خودکار **به انتهای لیست** منتقل می‌شوند
- موارد زیر آستانهٔ تعیین‌شده قرمز می‌شوند و از خروجی نهایی حذف می‌شوند
- مدیر می‌تواند نمره را صفر کند و ببیند چه کسانی رأی داده‌اند

**آمار**
- نمودار میله‌ای **روزانه (۳۰ روز)، هفتگی (۱۲ هفته) و ماهانه (۱۲ ماه شمسی)**
- تاریخ‌ها کاملاً شمسی، هفته از شنبه، بر مبنای ساعت تهران
- فعال‌ترین اعضای تیم و پراکندگی بین گروه‌ها
- امکان فیلتر آمار روی یک گروه خاص

**خروجی**
- دانلود `TXT` (فقط یوزرنیم‌ها، آمادهٔ آپلود در Telegram Ads)
- دانلود `CSV` (با نمره، یادداشت، ثبت‌کننده و تاریخ)
- کپی یک‌کلیکی کل لیست فیلترشده

**مدیریت**
- دو نقش: مدیر کل و کاربر عادی
- ساخت، ویرایش، غیرفعال‌سازی و حذف کاربر
- تاریخچهٔ کامل فعالیت‌ها
- جست‌وجوی سراسری بین همهٔ گروه‌ها
- تم تیره و روشن، کاملاً راست‌چین و فارسی، سازگار با موبایل

## نصب روی سرور اوبونتو

### پیش‌نیازها

- سرور اوبونتو ۲۰.۰۴ یا بالاتر (دبیان هم کار می‌کند)
- دسترسی `root` یا `sudo`
- یک دامنه یا زیردامنه که رکورد `A` آن به IP سرور اشاره کند (اختیاری ولی توصیه‌شده)

### روش ۱ — نصب مستقیم (توصیه‌شده)

چون مخزن خصوصی است، به یک **توکن دسترسی گیت‌هاب** نیاز دارید:

1. به <https://github.com/settings/tokens> بروید
2. **Generate new token (classic)** را بزنید و دسترسی `repo` را تیک بزنید
3. توکن ساخته‌شده را کپی کنید (با `ghp_` شروع می‌شود)

سپس روی سرور:

```bash
curl -fsSL -H "Authorization: token ghp_YOUR_TOKEN" \
  https://raw.githubusercontent.com/Cmd81/telegram-ads-panel/main/install.sh \
  | sudo GITHUB_TOKEN=ghp_YOUR_TOKEN GITHUB_REPO=Cmd81/telegram-ads-panel bash
```

> `ghp_YOUR_TOKEN` را با توکنی که در مرحلهٔ قبل ساختید جایگزین کنید.

### روش ۲ — کلون و نصب

```bash
git clone https://github.com/Cmd81/telegram-ads-panel.git
cd telegram-ads-panel
sudo bash install.sh
```

### در حین نصب چه چیزهایی پرسیده می‌شود

| پرسش | توضیح |
|---|---|
| **دامنه** | مثل `ads.example.com` — خالی بگذارید تا فقط روی `IP:PORT` بالا بیاید |
| **ایمیل** | برای گواهی SSL رایگان Let's Encrypt — خالی = بدون SSL |
| **پورت داخلی** | پیش‌فرض `8787` |
| **نام کاربری مدیر** | پیش‌فرض `admin` |
| **رمز عبور مدیر** | خالی بگذارید تا یک رمز امن ساخته و نمایش داده شود |

### نصب بدون تعامل (برای اسکریپت‌نویسی)

```bash
sudo NON_INTERACTIVE=1 \
     DOMAIN=ads.example.com \
     EMAIL=you@example.com \
     ADMIN_USER=admin \
     ADMIN_PASSWORD='یک-رمز-قوی-اینجا' \
     PORT=8787 \
     bash install.sh
```

### نصب‌کننده دقیقاً چه کار می‌کند

- ✅ اگر Node.js نسخهٔ ۱۸ به بالا روی سیستم باشد از همان استفاده می‌کند؛ **در غیر این صورت یک نسخهٔ اختصاصی داخل `/opt/channel-ads/runtime` نصب می‌کند و به بسته‌های سیستم دست نمی‌زند**
- ✅ کاربر سیستمی `chads` بدون امکان لاگین می‌سازد
- ✅ سرویس systemd با محدودسازی کامل دسترسی (`ProtectSystem=strict`، بدون capability، سقف حافظه ۵۱۲ مگابایت)
- ✅ اگر nginx نصب باشد فقط **یک فایل تنظیمات جدید** اضافه می‌کند و به سایت‌های دیگر دست نمی‌زند
- ✅ اگر Caddy یا Apache نصب باشد، تنظیمات آماده را چاپ می‌کند تا خودتان اضافه کنید
- ✅ قبل از هر نصب مجدد، از دیتابیس بکاپ می‌گیرد
- ✅ اگر پورت اشغال باشد یا تنظیمات nginx خراب شود، تغییرات را برمی‌گرداند

| کار | کاربر عادی | مدیر کل |
|---|:---:|:---:|
| دیدن لیست گروه‌ها | ✅ | ✅ |
| افزودن یوزرنیم به گروه | ✅ | ✅ |
| دیدن لیست یوزرنیم‌های گروه | ⚙️ | ✅ |
| ثبت نمرهٔ منفی | ⚙️ | ✅ |
| دیدن متن تبلیغ گروه | ⚙️ | ✅ |
| خروجی TXT / CSV | ⚙️ | ✅ |
| ساخت / ویرایش / حذف گروه | ❌ | ✅ |
| حذف یوزرنیم و صفر کردن نمره | ❌ | ✅ |
| انتقال یوزرنیم بین گروه‌ها | ❌ | ✅ |
| مدیریت کاربران | ❌ | ✅ |
| تنظیمات و تاریخچه | ❌ | ✅ |

**⚙️ = قابل تنظیم توسط مدیر** در صفحهٔ تنظیمات.

اگر «مشاهدهٔ لیست کامل» را خاموش کنید، کاربر عادی فقط ثبت‌های **خودش** را می‌بیند —
ولی **بررسی تکراری همچنان روی کل گروه انجام می‌شود**، پس داده تکراری وارد نمی‌شود.
این حالت وقتی مفید است که نمی‌خواهید لیست جمع‌آوری‌شده در اختیار همهٔ اعضا باشد.

## نحوهٔ کار با داشبورد

**۱. مدیر گروه می‌سازد**
صفحهٔ گروه‌ها ← «گروه جدید» ← عنوان، توضیحات و متن تبلیغ را وارد کنید.

**۲. اعضای تیم یوزرنیم اضافه می‌کنند**
وارد گروه شوید، لیست را در کادر بچسبانید و «افزودن به گروه» را بزنید.
می‌توانید ده‌ها کانال را یک‌جا paste کنید — سیستم خودش تفکیک می‌کند:

```
@crypto_news_ir
https://t.me/tehran_daily
t.me/sport_channel_pro
best_movies_channel
```

نتیجه بلافاصله نشان داده می‌شود: چند تا اضافه شد، کدام‌ها تکراری بودند و کدام خط‌ها قابل تشخیص نبودند.

**۳. کانال‌های ضعیف را علامت بزنید**
با دکمهٔ 👎 کنار هر یوزرنیم، نمرهٔ منفی ثبت کنید. آن مورد فوراً به ته لیست منتقل می‌شود.
هر کاربر یک رأی دارد و می‌تواند با کلیک دوباره پسش بگیرد.

**۴. خروجی بگیرید**
«خروجی TXT» یک فایل تمیز می‌دهد که کانال‌های زیر آستانهٔ نمرهٔ منفی از آن حذف شده‌اند —
آمادهٔ آپلود در Telegram Ads.

**۵. پیشرفت را دنبال کنید**
صفحهٔ آمار نشان می‌دهد هر روز/هفته/ماه چند یوزرنیم وارد شده و هر عضو تیم چقدر کار کرده است.

## مدیریت سرویس

```bash
sudo systemctl status channel-ads      # وضعیت
sudo systemctl restart channel-ads     # راه‌اندازی مجدد
sudo systemctl stop channel-ads        # توقف
sudo journalctl -u channel-ads -f      # لاگ زنده
sudo journalctl -u channel-ads -n 100  # ۱۰۰ خط آخر لاگ
```

### به‌روزرسانی

```bash
sudo GITHUB_TOKEN=ghp_YOUR_TOKEN GITHUB_REPO=Cmd81/telegram-ads-panel \
     bash /opt/channel-ads/update.sh
```

قبل از هر چیز بکاپ می‌گیرد، و اگر نسخهٔ جدید بالا نیامد **خودکار به نسخهٔ قبلی برمی‌گردد**.
پوشهٔ `data/` و فایل `app.env` هرگز دست نمی‌خورند.

### حذف

```bash
sudo bash /opt/channel-ads/uninstall.sh                 # داده‌ها به /root منتقل می‌شوند
sudo PURGE_DATA=1 bash /opt/channel-ads/uninstall.sh    # حذف کامل همراه داده‌ها
```

Node.js و nginx سیستم دست‌نخورده باقی می‌مانند و فقط فایل تنظیمات nginx مربوط به همین برنامه حذف می‌شود.

## پشتیبان‌گیری و بازیابی

تمام داده‌ها در **یک فایل JSON** ذخیره می‌شوند:

```
/opt/channel-ads/data/db.json          # دیتابیس اصلی
/opt/channel-ads/data/backups/         # بکاپ روزانهٔ خودکار (۲۱ روز اخیر)
/opt/channel-ads/data/sessions.json    # نشست‌های فعال
```

**بکاپ دستی:**
```bash
sudo cp /opt/channel-ads/data/db.json ~/backup-$(date +%F).json
```

از داخل داشبورد هم می‌توانید در صفحهٔ تنظیمات نسخهٔ کامل JSON را دانلود کنید (بدون رمزهای عبور).

**بازیابی:**
```bash
sudo systemctl stop channel-ads
sudo cp ~/backup-1405-06-17.json /opt/channel-ads/data/db.json
sudo chown chads:chads /opt/channel-ads/data/db.json
sudo systemctl start channel-ads
```

نوشتن روی فایل **اتمیک** است (نوشتن در فایل موقت و سپس `rename`)، پس قطع برق وسط ذخیره‌سازی
فایل را خراب نمی‌کند. اگر باز هم فایل خراب شد، برنامه خودکار از آخرین بکاپ سالم بازیابی می‌کند.

│   ├── index.html
│   ├── app.js              اپلیکیشن تک‌صفحه‌ای
│   ├── styles.css
│   └── favicon.svg
├── scripts/
│   ├── smoke-test.js       ۸۵ تست یکپارچهٔ API

## اجرای محلی برای توسعه

```bash
# اجرای ساده
node server/index.js

# با دادهٔ نمونه (۵ گروه و ۳۰۰+ یوزرنیم)
node scripts/seed-demo.js
DATA_DIR=./data-demo node server/index.js
```

سپس <http://127.0.0.1:8787> را باز کنید. رمز مدیر در خروجی ترمینال چاپ می‌شود.

**اجرای تست‌ها:**
```bash
node scripts/smoke-test.js     # تست API
bash scripts/test-install.sh   # تست اسکریپت نصب
```

**متغیرهای محیطی:**

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `8787` | پورت |
| `HOST` | `127.0.0.1` | آدرس bind |
| `DATA_DIR` | `./data` | مسیر ذخیرهٔ داده |
| `ADMIN_USER` | `admin` | نام کاربری مدیر اولیه |
| `ADMIN_PASSWORD` | (خودکار) | رمز مدیر اولیه |
| `TRUST_PROXY` | `1` | خواندن هدرهای `X-Forwarded-*` |
| `SECURE_COOKIE` | `0` | اجبار به کوکی `Secure` |
| `SESSION_DAYS` | `30` | مدت اعتبار نشست |
| `LOG_REQUESTS` | `0` | لاگ کردن هر درخواست |

## امنیت

- رمزهای عبور با **scrypt** و نمک تصادفی هش می‌شوند؛ هرگز به صورت متن ساده ذخیره نمی‌شوند
- کوکی نشست `HttpOnly` + `SameSite=Lax` (+ `Secure` وقتی SSL فعال است)
- محافظت **CSRF** با توکن اختصاصی هر نشست + بررسی هدر `Origin`
- **محدودسازی تلاش ورود**: ۸ تلاش ناموفق ← ۱۵ دقیقه قفل
- هدرهای امنیتی: `Content-Security-Policy` سخت‌گیرانه، `X-Frame-Options: DENY`، `nosniff`، HSTS
- تمام ورودی‌های کاربر در فرانت‌اند escape می‌شوند (بدون XSS)
- سرویس با کاربر بدون امتیاز و بدون هیچ capability اجرا می‌شود و فقط به پوشهٔ `data` دسترسی نوشتن دارد
- برنامه فقط روی `127.0.0.1` گوش می‌دهد و از طریق nginx در دسترس قرار می‌گیرد (وقتی دامنه دارید)
- فایل `data/` در `.gitignore` است و هرگز داخل مخزن نمی‌رود

**توصیه:** بعد از اولین ورود حتماً رمز پیش‌فرض را از منوی حساب کاربری تغییر دهید.

## رفع اشکال

**سایت بالا نمی‌آید**
```bash
sudo systemctl status channel-ads
sudo journalctl -u channel-ads -n 50
```

**خطای ۵۰۲ از nginx**
یعنی nginx بالاست ولی برنامه نه. سرویس را ری‌استارت کنید و پورت را بررسی کنید:
```bash
sudo systemctl restart channel-ads
grep PORT /opt/channel-ads/app.env
```

**گواهی SSL گرفته نشد**
معمولاً یعنی رکورد `A` دامنه هنوز به IP سرور اشاره نمی‌کند. بعد از تنظیم DNS:
```bash
dig +short ads.example.com     # باید IP سرور را نشان دهد
sudo certbot --nginx -d ads.example.com
```

**رمز مدیر را فراموش کرده‌اید**
```bash
sudo systemctl stop channel-ads
sudo -u chads /opt/channel-ads/runtime/bin/node -e "
  process.env.DATA_DIR='/opt/channel-ads/data';
  const s=require('/opt/channel-ads/server/store');
  const a=require('/opt/channel-ads/server/auth');
  s.load();
  const u=s.get().users.find(x=>x.role==='admin');
  u.passwordHash=a.hashPassword('رمز-جدید-شما');
  u.active=true; s.flush();
  console.log('رمز کاربر '+u.username+' تغییر کرد.');
"
sudo systemctl start channel-ads
```
> اگر از Node.js سیستم استفاده می‌کنید، به‌جای مسیر `runtime/bin/node` فقط `node` بنویسید.

**تغییر پورت**
```bash
sudo nano /opt/channel-ads/app.env      # مقدار PORT را عوض کنید
sudo nano /etc/nginx/sites-available/channel-ads   # proxy_pass را هم عوض کنید
sudo systemctl restart channel-ads && sudo systemctl reload nginx
```
